DataPilot: a self-correcting AI data analyst

Ask a business question in plain English about a CSV or Excel file. A team of AutoGen agents plans the analysis, writes Python, runs it in a sandbox, fixes its own errors and gets reviewed, then returns an answer with charts, a re-runnable analysis.py and a one-page PDF.

01 · Challenge

The problem worth solving

Business teams have data and questions, but they wait days for an analyst to write the code. Handing the job to an LLM sounds easy, and on clean demo data it mostly works.

On real exports it fails quietly. Three date formats in one column, prices stored as text, “North” and “north ” counted as different regions: the code runs, nothing crashes, and the answer is confidently wrong. The real problem was turning silent wrong numbers into errors an agent can see and fix.

02 · Approach

How I built it

  • One job per agent. The Planner sees only the column schema and five sample rows and writes a 3–6 step plan. The Coder writes one complete pandas and matplotlib script. The Executor runs it. The Reviewer checks every part of the question against the printed numbers and chart labels.
  • Routing by rules. A SelectorGroupChat with a rule-based selector: an Executor error goes back to the Coder, a clean run goes to the Reviewer, and Reviewer feedback goes to the Coder. LLM-based selection and round-robin are available as alternatives.
  • A sandbox that criticises. Code runs in a sandbox folder or a Docker container with unsafe calls such as subprocess, network access and file deletes blocked. A data_check() gate raises when more than 2% of rows are dropped, dates fail to parse or swap day and month, or one value is spelled two ways. Every chart must have a title, axis labels and units.
  • Bounded by design. The run stops on the Reviewer's APPROVED or after 12 messages, so it can never loop forever. The public app also caps live runs per day.
  • Human in the loop. A UserProxyAgent lets you approve the answer or ask a follow-up that continues the same session.

04 · Agent roles

What each agent does

Planner

AssistantAgent. Reads the question and schema, never the full data, and writes the plan.

Coder

AssistantAgent. Writes one complete script, and rewrites it on an error or on feedback.

Executor

CodeExecutorAgent with a local or Docker executor. Tags STATUS: OK or ERROR, saves analysis.py, tracks charts.

Reviewer

AssistantAgent. Checks numbers and labels, then replies FEEDBACK: or the final answer plus APPROVED.

You

UserProxyAgent. Approve the result or ask a follow-up in the same session.

Outputs

Plain-English answer, PNG charts, a re-runnable analysis.py and a one-page PDF report.

Guardrails & safety

Built to be safe in production

Live, tested protections in the deployed app, not just a demo.

Code sandbox

Agent-written Python is checked with an AST allow/deny list, then run with no secrets, a CPU, memory and file-size budget, and network and outside-folder access blocked.

Input limits

CSV/XLSX only, 10 MB, row and column caps and a question length limit. Off-topic or harmful requests are declined.

Prompt-injection defence

File names and cell values are wrapped as untrusted data, and every agent is told to ignore instructions found inside the data.

Cost & abuse caps

Limits on agent turns, tokens per call and run time, 5 runs per hour per visitor and a daily cap.

Locked-down container

Runs as non-root with all Linux capabilities dropped. Answers are format-checked and keys and server paths are scrubbed.

06 · Result

What it delivers

In six final live runs on a deliberately messy Excel export, DataPilot answered six of six correctly, and four of the six fixed at least one real error on their own. Before the sandbox checks existed, the same runs were often approved with wrong numbers.

Re-running the saved analysis.py gives exactly the same numbers, so every answer can be checked and reused.
